What our ShopFlow rehearsal taught us

One visible error can hide several separate problems

The function first stopped because DB_CA_CERT was missing and the deployed variable names did not match the code. Behind that, the read-only database user was absent and all seven tables were empty because the Colab load did not finish. A stale notebook output made the load look successful, and an administrator credential had been placed in notebook code.

The lesson: do not guess or change everything at once. Find the first broken handoff, repair it, then test the next one. If a credential was exposed, rotate it before continuing and move it into a secret store.

1 Build the mental model

Follow one request all the way around

The browser never connects directly to MySQL and never receives a database password. Each layer has one job.

  1. 1
    BrowserYou click Products, Search, or an Analytics button.
  2. 2
    Netlify pageapp.js sends a same-origin GET request.
  3. 3
    Netlify FunctionServer-side code reads protected configuration and prepares a parameterized query.
  4. 4
    Aiven MySQLThe shopflow_reader account runs a read-only SELECT over TLS.
  5. 5
    JSONThe function returns selected rows as data—not as database credentials.
  6. 6
    BrowserThe page turns the JSON into product cards, a customer result, or an analytics table.

Why “same origin” matters

The page calls /.netlify/functions/products, a path on the same deployed ShopFlow site. It should not contain an old Netlify domain, an Aiven hostname, or a direct MySQL connection. The relative path lets the browser contact its own server-side function without publishing secrets or creating an unnecessary cross-origin request.

2 Locate the break

Start with the smallest safe test

Page test

Does the ShopFlow page load?

If the page itself is missing, solve the deployment or file-path problem before investigating MySQL.

Function test

Does the products endpoint return JSON?

Open /.netlify/functions/products. A JSON array means the page-to-function route works. An error object plus a status code tells you where to look next.

  1. 1
    Write down the action. Example: “I reloaded Products at 2:14 p.m.”
  2. 2
    Open Developer Tools → Network. Select the request beginning with /.netlify/functions/.
  3. 3
    Record only safe evidence. Note the path, method, status code, and sanitized error message. Do not capture request headers, environment variables, connection strings, or credentials.
  4. 4
    Fix one layer. Redeploy when configuration or function code changes, then repeat the same test.
3 Let the response guide you

The status code is a road sign

Common ShopFlow HTTP responses and what to check first
StatusPlain meaningFirst place to look
404 The requested page or function path was not found. Spelling, deployed file, function filename, and the current production deploy. A 404 does not prove the database is down.
400 The function received the request, but the input was invalid or missing. Required query parameters. For example, Search needs ?q=term and Analytics needs a supported ?query= value.
405 The path exists, but the HTTP method is not allowed. Use GET. ShopFlow’s public functions are deliberately read-only and reject POST, PUT, and DELETE.
500 The function started and then failed on the server. Netlify Function logs, exact environment-variable names, TLS certificate, Aiven service, reader access, schema, or SQL.
200 The request succeeded. An empty array [] still counts as success. If the page is empty, check table row counts, active-status filters, search text, and joins—not the network connection.
4 Repair the server connection

Check configuration by name, purpose, and scope

Netlify variable names are case-sensitive. host and DB_HOST are different names. ShopFlow expects exactly these six keys; the values stay private.

  • DB_HOSTAiven service host
  • DB_PORTAiven service port
  • DB_USERRead-only website account
  • DB_PASSWORDReader account secret
  • DB_NAMEShopFlow schema name
  • DB_CA_CERTComplete Aiven CA certificate

Classify secrets without disabling the scanner

Mark DB_PASSWORD and DB_CA_CERT as secret values. Keep DB_HOST, DB_PORT, DB_USER, and DB_NAME as ordinary environment variables, while still keeping their values out of student evidence. If a common value such as shopflow or shopflow_reader is marked as a secret, Netlify can correctly find that same text in the README or tests and stop the build. Reclassify the variable and redeploy; do not turn off secret scanning.

Never put the values in browser JavaScript. Do not commit a .env file or paste passwords, certificates, tokens, connection strings, or screenshots of them into GitHub, Canvas, chat, or an AI prompt. If a credential is exposed, rotate it first. For a shared class resource, stop and notify the instructor.
TLS

Keep the certificate complete

DB_CA_CERT must include the beginning line, ending line, and preserved line breaks from the CA certificate for the same Aiven service.

Do not “fix” TLS by setting rejectUnauthorized to false. Correct the certificate instead.

Least privilege

Deploy the reader—not the administrator

The website should connect as shopflow_reader with SELECT on shopflow.* only. The administrator account is for initial setup and recovery, never for Netlify.

Connected as the reader, SHOW GRANTS; should not show INSERT, UPDATE, DELETE, or administrative privileges.

Redeploy

Configuration changes need a fresh run

After adding or correcting Netlify variables, trigger a new deploy and wait until it is published. Testing an older deploy only repeats the old configuration.

5 Prove the data exists

A successful connection can still return no products

Notebook output is like a photograph: it shows what happened during an earlier run, not what the current cell or database contains now. A printed “rows loaded” message is not proof until MySQL reports the rows.

Use Colab without exposing credentials

  1. Store private connection values in Colab Secrets using the key icon—not in a code cell.
  2. Restart or reconnect the runtime if needed, then run required cells in order.
  3. Confirm each CSV was actually read and cleaned. Check the current DataFrame row count.
  4. Run the load cell and wait for completion. An interrupted cell did not finish just because older output remains visible.
  5. Do not rerun a schema-reset cell after loading unless you intend to erase the tables and immediately reload all seven files. Keep the guarded reset switch off during normal work.
  6. Query MySQL after the load. Compare table counts with the cleaned DataFrame counts and investigate every mismatch.

Run this read-only row-count check in the shopflow schema

SELECT 'customers' AS table_name, COUNT(*) AS row_count FROM customers
UNION ALL SELECT 'products', COUNT(*) FROM products
UNION ALL SELECT 'orders', COUNT(*) FROM orders
UNION ALL SELECT 'order_items', COUNT(*) FROM order_items
UNION ALL SELECT 'reviews', COUNT(*) FROM reviews
UNION ALL SELECT 'abandoned_carts', COUNT(*) FROM abandoned_carts
UNION ALL SELECT 'support_tickets', COUNT(*) FROM support_tickets;

Interpret the result: missing tables mean schema creation or naming failed; zero rows mean the load did not persist; counts lower than the cleaned CSVs mean the load was partial or rows were rejected. Load parent tables such as customers and products before child tables that reference them.

6 Read the server’s evidence

Match one failed request to one Function log

The browser normally sees a safe message such as “Database request failed.” The Netlify Function log contains the useful server-side clue.

DB_CA_CERT is not configured

The exact key is absent, misspelled, lowercased, scoped incorrectly, or not included in the current deploy.

Access denied for user

Check that the reader account exists, its private value is current in Netlify, and it has SELECT on shopflow.*.

unable to verify…

The CA is missing, incomplete, has damaged line breaks, or came from a different service. Replace the certificate; do not disable verification.

ECONNREFUSED / ETIMEDOUT

Check whether Aiven is running and whether the private host and port are correct. Do not paste either value into a report.

Table … doesn't exist

Confirm DB_NAME, the seven table names, and that schema creation completed in the intended database.

200 with []

This is not a connection error. Check row counts, status = 'Active', search input, date filters, and join conditions.

A good log routine

Note the test time → run one request → open that function’s log → find the matching timestamp → read the first meaningful error → fix that layer → redeploy → repeat. Share only a redacted excerpt if you need help.
